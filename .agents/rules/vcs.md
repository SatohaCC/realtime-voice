# バージョン管理（Git）ルール

- このリポジトリは **Git** で管理する。
- 状態確認・履歴操作には `git`（`git status`, `git diff`, `git log`, `git switch`, `git add`, `git commit` 等）を使う。

## 作業開始と変更の確認

- 作業前に `git status`、`git diff --stat`、必要な範囲の `git log` で現在の変更・ブランチを確認する。既存のユーザー変更を保持し、依頼した作業の範囲を区別する。
- 作業用ブランチが必要なら、既存の運用を確認し、新規ブランチ名は原則 `codex/` を接頭辞にする（例: `git switch -c codex/<topic>`）。

## コミットと変更の分離

- コミットを依頼されたときは `git status` と `git diff` で対象を確認し、依頼外の変更を混ぜない。変更が混在している場合は、ファイル単位や `git add -p` 等でステージングを分離し、無条件に `git add -A` 等ですべてを確定しない。
- コミットメッセージは **Conventional Commitsの形式で、説明を日本語** にする。例: `chore: 初期テンプレートを整備`。
- `git reset --hard` / `git checkout --` / `git restore` / `git clean` / 広範な rebase 等を、既存変更の消去やエラーの隠蔽に使わない。影響するブランチと作業ツリーを確認し、依頼の範囲内で行う。

## 検査と不要ファイルの除外

- コミット前に `pnpm check` や関連テストで検証する（最終的な検証は CI でも行う）。
- `.venv`、キャッシュ、実行ログ、ローカルの絶対パスを含めない（`.githooks/pre-commit` がステージ内容のローカルパス混入を検査する）。
- 追跡済みの不要ファイルは `git rm --cached <対象>` で追跡を外し、必要に応じて `.gitignore` に追加する。
- 最終差分・コンフリクト・コミットメッセージ・ブランチを確認し、実行した検証と未実行の検証を区別して報告する。

## リモート操作

- push はユーザーから明示的に依頼・承認された場合のみ行う。
- push 前に `pnpm check`、送信するブランチ・コミット、履歴にローカルパスやコンフリクトが残っていないかを確認する。
- `git push <remote> <branch>` のように対象を明示し、`--all` や `--force` を既定にしない。
